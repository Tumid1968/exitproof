# NOTES — décisions prises en autonomie

1. Le cache de fork de `_preflight/` n'est pas copié (règle CLAUDE.md) : il est reconstruit par une exécution en ligne.
2. Le proxy garde son propre cache disque des requêtes déterministes (bloc explicite). Il sert aussi la découverte des dépendances hors connexion. Les requêtes « latest » ne sont jamais mises en cache.
3. dRPC gratuit limite `eth_getLogs` à 10 000 blocs par requête.
4. dRPC gratuit ne sert `eth_getLogs` que près de la tête de chaîne (et limite le débit) : impossible d'énumérer l'historique d'événements. **Décision** : l'API publique Morpho (GraphQL) sert uniquement à lister des *candidats* (coffres qui fournissent un marché, emprunteurs). Chaque candidat est relu par `eth_call` au bloc figé, et la complétude est mesurée on-chain (Σ parts trouvées / parts totales du marché : 100 % de la dette identifiée pour les 3 marchés exposés de Steakhouse ETH). Les réponses de l'API sont en cache disque pour le mode hors connexion.
5. L'API reflète l'état « actuel » (~3 000 blocs après le bloc figé) : un emprunteur fermé entre-temps serait manqué ; la couverture on-chain le révélerait (< 100 %).
6. Liquidateur des scénarios de choc : adresse fixe impersonée `0x…E1F0`, financée en ETH local puis WETH. Hypothèse affichée : les liquidateurs ont le capital et liquident tout. Le régime « liquidations bloquées » est représenté par le cas « oracle aveugle ».
7. Perte économique du décrochage aveugle = Σ max(0, dette − collatéral × prix de marché choqué) des emprunteurs, au prorata des parts du coffre. Hypothèse : le décrochage persiste et les emprunteurs sous l'eau ne remboursent pas. Ce n'est pas une perte constatée on-chain : affiché comme tel.
8. Probabilité d'incident par défaut dans le rapport (5 % sur 30 jours) et décote du bloqué (10 %) : valeurs de démonstration, modifiables dans l'interface, présentées comme hypothèses de l'utilisateur.
9. Hardhat 3 ne supporte pas `hardhat_reset` : l'identifiant du snapshot de base est persisté dans `cache/fork-base-snapshot.json` pour revenir à l'état source entre deux processus.
10. **Bug Hardhat 3 / EDR constaté** : `evm_revert` ne restaure pas de façon fiable le code posé par `hardhat_setCode` sur un compte forké ; un oracle remplacé fuyait dans le scénario suivant (vu sur Steakhouse USDC : prix de départ déjà ×0,95). Correctif : le code original est relu sur l'archive (proxy, bloc figé) et réinstallé avant et après chaque scénario ; garde-fou : le prix avant choc doit être égal à `price()` lu sur l'archive au bloc, sinon erreur. Les résultats Steakhouse ETH n'étaient pas touchés (prix avant choc = prix source, vérifié).
11. Pipeline générique (`src/scenarios/generic.ts`) pour tout coffre V1 : détenteur cible = le plus gros (ou un détenteur donné), sorties concurrentes = les 3 suivants + le n°1 des 3 coffres pairs qui partagent le plus de liquidité, choc = le feed le plus dommageable à −10 % (balayage analytique), décrochage aveugle du collatéral principal. Steakhouse ETH garde le catalogue « curated » qui reproduit les valeurs de référence.
12. Gaz : payé en ETH. Pour un coffre non-ETH (USDC), il n'est pas converti (pas de prix sourcé) : coût compté à 0 dans le verdict et affiché à part.
13. Validation hors connexion complète (sam. ~11:50) : proxy en mode offline, nœud Hardhat neuf, `EXITPROOF_OFFLINE=1 npm run all` → découverte, 13 scénarios exécutés et replay verts pour les 3 coffres. Seule requête refusée : `eth_feeHistory` (sans effet).
14. Découverte rendue déterministe (coffres pairs traités séquentiellement) : deux exécutions produisent des fichiers de graphe identiques octet par octet.
15. Couche AMM : capacité = borne basse (Uniswap V3 + Curve seulement, pools directs additionnés + meilleure route en deux sauts via WETH). Hypothèse : la profondeur suit le prix choqué. Le budget de liquidation est partagé entre marchés d'un même collatéral (mêmes pools), servi d'abord aux marchés à plus forte prime.
16. **Bug corrigé (sam. ~12:10)** : dans le décrochage « aveugle », le facteur était appliqué deux fois (prix × f × f). Le manque économique annoncé à −10 % (~910 WETH) correspondait en fait à ~−19 %. Valeur corrigée : 219,0 WETH pour le coffre, point mort 1,13 % (et non 0,69 %). Test unitaire sur graphe synthétique ajouté (`test/analytic.test.ts`), il aurait détecté l'erreur. Tous les résultats, README et DEMO régénérés.
